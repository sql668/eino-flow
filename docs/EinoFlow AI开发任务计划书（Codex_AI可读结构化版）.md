# EinoFlow AI开发任务计划书（Codex/AI可读结构化版）

## 1\. 项目全局信息（AI 必须优先读取）

**项目名称**：EinoFlow

**项目定位**：类 Dify 低代码 AI 工作流/智能体平台，基于字节 Eino 作为底层编排内核，Go 高性能架构，自带插件市场、MCP 工具生态、全链路可观测，对标并超越 Dify。

**仓库结构**：单仓库简易 Monorepo（无重型构建工具）

**运行方式**：本地开发 \+ Docker Compose 一键部署

**项目目标**：

- V0\.1：快速可用 Demo（RAG \+ ReAct 智能体 \+ 流式对话）

- V1\.0：完整复刻 Dify 全部核心能力（画布工作流、知识库、应用管理、模型管理）

- V2\.0：差异化升级（插件市场、MCP 协议、多智能体、全链路可观测、热执行引擎）

---

## 2\. 全局技术栈（AI 严格遵守）

### 2\.1 前端技术栈（Web）

- 框架：Next\.js 14\+ App Router（TS）

- UI 语言：TypeScript 严格模式

- 画布引擎：@xyflow/react（ReactFlow 最新版）

- 状态管理：Zustand（轻量、画布全局状态）

- 样式：TailwindCSS \+ shadcn/ui

- 代码编辑器：Monaco Editor

- 网络：自定义 SSE/HTTP 统一请求封装

- 核心产出：画布 DSL 序列化、工作流配置管理、插件市场 UI、对话调试

### 2\.2 后端技术栈（Backend）

- 框架：Golang \+ Hertz（CloudWeGo）

- AI 内核：CloudWeGo Eino（Graph/Workflow/ReAct/Agent/Memory）

- 数据库：PostgreSQL（业务数据）

- 向量库：Milvus（RAG 检索）

- 对象存储：MinIO（文档文件存储）

- 缓存：Redis（会话、限流、缓存）

- 可观测：OpenTelemetry \+ Eino Callback 链路追踪

- 扩展协议：MCP 工具协议适配层

---

## 3\. 前后端模块边界（AI 严格区分）

### 3\.1 前端只负责的模块（不处理任何 AI 逻辑）

- 用户界面、页面路由、表单交互

- 工作流画布拖拽、节点配置、连线、变量拾取

- 画布状态管理、撤销重做、小地图、缩放

- 知识库文件上传、进度展示、列表管理

- 模型密钥配置页面

### 3\.2 后端只负责的模块（所有 AI 核心在这里）

- DSL 解析器：前端 DSL \-\> Eino Graph 动态构建

- Eino 工作流/Agent 运行时、节点执行、分支调度

- RAG 完整管线：解析、切片、向量化、入库、检索

- 多模型适配层、密钥管理、模型调用

- 插件系统内核：插件注册、加载、沙箱、执行

- MCP 工具协议对接、远程工具调用

- 全链路 Trace、Token 统计、执行日志

- 业务 CRUD、权限、会话、API 输出

## 5\. 三阶段严格开发计划（AI 按阶段执行，禁止跨阶段）

### 阶段一：V0\.1 极速可用 Demo（优先开发、最快落地）

**阶段目标**：不做拖拽画布，优先保证后端 Eino 核心跑通，快速产出可演示项目

**前端可做**：

- 基础页面布局：登录、应用列表、知识库、对话页

- 表单式应用配置（暂时不拖拽）

- SSE 流式对话调试页面

- 知识库上传、列表展示

**后端必须完成（核心优先级最高）**：

- Eino 基础封装：ChatModel / Embedding / Memory

- ReAct Agent 基础工具调用

- RAG 完整入库\+检索链路

- Hertz 流式 SSE 接口

- 基础数据库表结构与 CRUD

**阶段禁止做**：拖拽画布、插件市场、MCP、多智能体、完整观测面板

### 阶段二：V1\.0 对标 Dify 完整版

**阶段目标**：完全对齐 Dify 所有核心功能

**前端新增**：

- xyflow 完整拖拽画布

- 所有工作流节点 UI

- 变量系统、连线校验、撤销重做

- 画布 DSL 完整序列化

**后端新增**：

- DSL 解析器 \+ 动态 Eino Graph 构建引擎

- 所有工作流节点执行逻辑（条件、循环、代码、HTTP 等）

- 应用发布、API 对外开放能力

- 完善模型管理、密钥管理

### 阶段三：V2\.0 差异化亮点终极版（碾压 Dify，简历王炸）

**阶段目标**：打造 Dify 不具备的独家能力

**后端重点新增**：

- 完整**插件市场内核**（插件注册、热加载、版本、沙箱）

- **多智能体协同引擎**（Host\+子Agent、并行执行、任务委派）

- **MCP 通用工具协议适配层**

- **全链路 OTel 可观测系统**

- 工作流热执行、无重启更新

**前端重点新增**：

- 插件市场完整 UI（广场、安装、管理、开发者中心）

- 链路追踪可视化面板、执行日志图谱

## 7\. AI 开发约束规则（硬性）

- 禁止前端写任何 AI 执行逻辑，所有 AI 运行必须后端 Eino 控制

- 所有工作流运行必须通过「前端DSL \-\> 后端解析 \-\> 动态Eino Graph」流程

- 所有配置持久化到 PostgreSQL，禁止硬编码

- 严格按照三阶段开发，不提前开发高阶功能

- 后端代码分层严格：handler \-\> service \-\> engine \-\> repository

- 前端状态统一 Zustand，禁止零散状态管理

- 所有接口、DSL、结构体必须有严格 TS/Go 类型定义
