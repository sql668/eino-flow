# Proposal

## Why

技术债 17：入库自动抽取的分段关键词里会混入「断开电」「交流电压测」这类**字符片段**，需要人工清理。
根因不是启发式不够，而是**没有词典**：现在的本地分词器已经把"不用词典能做的"做满了四道
（频次阈值、左右邻字多样性、首尾虚词表、长词优先的子串抑制），但无论怎么调，它都无法知道
「断开电源」是词而「断开电」不是——更长候选若在整篇文档里只出现一两次，就进不了候选池。

这不只是观感问题：关键词会被拼进 BM25 的输入文本，**重复出现即等于加权**；抽出来的是切断片段时，
服务端分析器会再切一遍，加权就落到了错误粒度上（「断开」+「电」）。

## What Changes

- 引入带词典的纯 Go 分词器（`github.com/go-ego/gse`，MIT），实现既有的 `keyword.Tokenizer` 接口，
  流水线不改——这个接口本来就是为换实现留的（见 `local_tokenizer.go` 的注释）；
- 保留现有启发式作为**后置过滤层**（子串抑制 + 首尾虚词边界），只把"候选生成"换成词典分词；
- 支持**自定义词典**补充领域词（「万用表」「示波器」这类通用词典未必收录的专业词）；
- 用**两套分词器在真实样本上做对比实测**（`docs/rag-test` 样本 + 现有 23 段手册），用数据决定切换；
  若专业词反而被切碎，就补进自定义词典再评；
- 已入库文档的关键词**不自动重算**（避免一次全量重算打乱演示环境），需要时重走分段工作台。

不做（明确排除）：

- 不升级 Milvus 用服务端分析器（技术债 18）——它的收益"抽词与索引分析器同口径"与现状重叠
  （索引侧本来就会把拼接文本重新切一遍），代价却是版本升级 + 数据卷/集合重建 + 全链路回归；
- 不改关键词的数量上限、开关语义与检索算法；
- 不把自定义词典做成配置项（先代码内置，见 design D4）。

## Capabilities

### New Capabilities

（无。）

### Modified Capabilities

- `rag-pipeline`: 关键词抽取要求——从"文本统计抽词"改为"以带词典的分词结果为依据"，并新增"领域词可通过自定义词典补充"。

## Impact

- 后端：`internal/engine/rag/keyword`（新增实现与测试）、`go.mod` / `go.sum`（新增依赖）、
  可能新增一个分词器选择配置项（用于回退与对比）；
- 部署形态：**不变**（gse 支持内嵌词典，不引入外部词典文件、不新增容器或挂载）；
- 数据：已入库关键词不迁移；重新入库的文档使用新抽取结果；
- 检索行为：关键词内容变化会改变 BM25 输入文本，需要回归（对比实测 + 端到端命中对比）。
