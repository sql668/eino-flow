# Design

## Context

现状：`internal/engine/rag/keyword/local_tokenizer.go` 用无词典统计法抽词（CJK 串内穷举 2~6 字候选，
按频次、左右邻字多样性、首尾虚词、长词优先的子串抑制四道规则筛选）；关键词同时进 PostgreSQL 与
Milvus 的 BM25 输入文本，界面上可人工增删改。
接口：换实现只需替换 `keyword.Tokenizer`，流水线（`engine/rag/pipeline.go`）不用动。
约束：`backend/AGENTS.md` 要求新增依赖先说明用途；根 `AGENTS.md` 要求"能用手写小工具解决的就不引依赖"
——这条已经在下面 D1 里正面回答（现有启发式已用满，剩余问题是词典问题，不是工具问题）。

## Goals / Non-Goals

- Goals：关键词候选**是词**而不是字符片段；领域词有补充通道；切换可回退、有数据支撑。
- Non-Goals：不做词性标注与更复杂的 NLP；不追求与 BM25 分析器同口径（那条约束现在并没被破坏：
  索引侧与查询侧都是服务端分析器，真正要紧的一致性在这里）；不动检索算法与阈值语义。

## Decisions

**D1 用带词典的分词器，而不是继续堆启发式**
理由：现有四道规则已经是无词典方案的上限（见 Context），残余缺陷的根因是"不知道哪些是词"。
备选：继续加启发式——边际收益低、规则越来越难解释；升级 Milvus 用服务端分析器——成本高、收益重叠。

**D2 用内嵌词典，不用外部词典文件**
理由：部署形态保持不变（不新增挂载、不改镜像、不新增初始化步骤）。gse 同时支持
`LoadDict`（外部文件）与内嵌加载，我们只用内嵌路径。代价是二进制体积与内存上升——
**必须实测并把数字记录在案**（见 tasks 1.2），这是"是否继续用内嵌词表"的判断依据。

**D3 词典只负责"候选是词"，后置过滤层保留**
理由：能切成词 ≠ 是关键词。子串抑制与虚词边界过滤与词典是正交能力，保留它们可以让新实现不倒退。
被否方案：完全换成词典分词就结束——会把现有已经压掉的噪声重新放出来。

**D4 自定义词典先代码内置，不做配置项**
理由：当前唯一确定的领域词来源是"我们自己知道哪些专业词"（万用表、示波器、函数发生器……），
一个内置表就够；做成配置项会引出"谁来维护、存在哪、版本怎么对齐"的问题（YAGNI）。
若实测发现需要频繁调整，再升级为配置项，届时是一次独立的变更。

**D5 用配置项选择分词实现，默认切到词典**
理由：对比实测（tasks 3.1）本身就需要两套实现并存；配置项同时提供了回退路径。
代价是多一个配置项——比"改坏了没法快速回退"便宜得多。

**D6 已入库文档的关键词不自动重算**
理由：重算需要重新切片+重写向量（全量动作），会把演示环境的水位打乱；而关键词本来就允许人工编辑。
需要时走"重新入库/重切"即可（既有功能）。因此本 change 的规格不涉及迁移语义。

## Risks / Trade-offs

- [专业词被切得更碎，反而比现状差] → tasks 3.1 的对比实测把关；退化词补进 D4 的自定义词典再评
- [二进制体积与常驻内存上升] → tasks 1.2 实测记录；若不可接受，换更小的内嵌词表（不是放弃方案）
- [词典初始化耗时压到启动路径] → 启动时一次性初始化并记录耗时，绝不放请求路径
- [关键词变化影响既有检索结果] → tasks 5.2 用同一问题对比新旧关键词下的命中，确认没有退化

## 迁移计划

1. 先加实现与配置项（默认仍走现状实现），跑对比实测；
2. 数据达标后再把默认切到词典实现（一次提交只做这一件事）；
3. 回滚：配置项切回统计实现即可，不需要回滚数据；
4. 已入库关键词保持原样，重新入库的文档才使用新实现。

## Open Questions

- 自定义词典是否最终需要配置化（本 change 不做，见 D4；等出现真实维护需求再定）。

## 实测数据（2026-10-18）

**部署形态**：把关键词包的测试二进制复制到 `/tmp` 下一个不含任何词典文件的空目录运行，
分词仍正常，确认走的是内嵌词表。

| 项 | 改造前 | 改造后 |
| --- | --- | --- |
| 后端二进制 | 53 MB | 85 MB（+32 MB，内嵌词表） |
| 后端常驻内存（RSS） | 38.3 MB | 135.9 MB（+97.6 MB，MinTokenFreq=30） |
| 词典初始化耗时 | — | 约 300 ms |

调参过程：

- 完整词表（MinTokenFreq=2，35 万词）：初始化 2.1 s、RSS 261.5 MB，**不采用**；
- MinTokenFreq=100（3.6 万词）：RSS 117.5 MB，但会把「前请」「先断」粘成词，**不采用**；
- MinTokenFreq=30（6.8 万词）：初始化 300 ms、RSS 135.9 MB，作为默认。

**对比样本**：用 MinerU 解析 `docs/rag-test` 的手册 PDF（167 个段落），
与 23 段入库手册同源。

- 改善：`断开电` → `断开电源`；`交流电压测` → `交流电` / `电压`；
  `开电池后盖` → `打开` + `电源`；`更换 电池` → `更换电池`；
  新增 `说明书`、`万用表`、`液晶显示`、`短路`、`保险丝` 等完整词；
- 退化 / 残余：词典词仍可能是泛词（`允许`、`可能`、`导致`）并在 TF-IDF 下排到前列；
  已把实测被切碎的仪器术语（`背光灯键`、`功能转盘`、`短路蜂鸣`、`测量值` 等）补进领域词。
  词性过滤（只保留名词/动词）不在本 change 范围内。
