# Proposal

## Why

V0.1 目标写的是「ReAct / RAG 问答」，目前只完成了 RAG 那一半：
应用形态为 `agent` 的对话在入口被明确拒绝（不静默降级）。Eino 已提供 ReAct 组件，
缺的是「把知识库检索注册成工具 + 运行时 + 前端形态落地」这三件事。
补齐它，V0.1 才算真正收口。

## What Changes

- 新增智能体问答能力：以 ReAct 循环执行，把知识库检索注册为内置工具，工具结果回灌后继续推理；
- 同时注册一个**无副作用的演示工具（计算）**：不依赖任何外部服务，用来证明"工具机制"本身可用
  （多步问答里模型会先算再答），也为后续接入真实工具提供样板；
- 一次问答的工具调用过程（工具名、入参、结果摘要、失败原因）作为**独立流式事件**返回前端；
- 工具调用轮次上限**可配置**，默认最多 **3** 次；达到上限时结束并说明（避免成本失控与重复检索）；
- 工具调用过程**默认展示**，界面上可**手动关闭**；关闭只影响展示，不影响工具执行与记录；
- 检索范围**沿用现状**：一次问答最多一个知识库（不新增应用级绑定）；工具入参按列表设计、当前只接受 1 个，
  传入多个直接报错——为 V1.0 的多知识库留扩展位而不提前实现；
- 修改对话形态路由：`agent` 形态从「明确拒绝」改为走智能体链路；`workflow` 形态仍然拒绝（属于 V1.0）；
- 前端：应用形态选择放开 `agent`；对话调试页新增工具调用块（可折叠，展示入参与结果摘要）；
- 会话消息需要能承载工具调用记录（新增消息类型或字段），否则刷新后看不到「为什么这么答」。

不做（明确排除）：

- 多知识库协同检索（跨库分数可比性、TopK 分配、去重、引用带库名）——留给 V1.0 独立 change；
- 多智能体协同、工具商店 / 第三方工具市场、任意 HTTP 工具自定义（都属于 V2.0）。

## Capabilities

### New Capabilities

- `agent-chat`: 智能体问答的工具注册、ReAct 执行循环、工具调用过程的可观测性与终止条件。

### Modified Capabilities

- `chat-conversation`: 对话形态路由变化——`agent` 形态由「明确拒绝」改为走智能体链路。

## Impact

- 后端：`internal/engine`（新增智能体运行时与工具注册表，遵守 `backend/AGENTS.md` 的分层）、
  `service/chat.go`（按应用形态选择链路）、`handler/chat.go`（新增工具类事件）；
- 前端：`web/app/(console)/apps`（形态选项）、`web/components/chat`（工具调用块）、`web/types/api.ts`（事件类型）；
- 依赖：使用 Eino 自带的 ReAct / Agent 组件，属于既定技术栈，**不新增第三方依赖**；
- 数据：`messages` 需要承载工具调用记录（迁移脚本 `0011_*`）；
- 复用：知识库检索复用现有 `engine/rag` 检索器，不新写一套检索。
