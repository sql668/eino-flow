# Design

## Context

对话链路的依赖已经通过接口隔离：模型走 `engine/model` 的接口与 resolver，检索走 `engine/rag` 的检索器，
事件经 `handler/chat.go` 以 SSE 输出。这意味测试可以在不触碰真实服务的前提下替换掉最外层实现。
已有的测试习惯（表驱动、集成测试用环境变量开关）见 `make backend-test` 与既有 21 个测试文件。

## Goals / Non-Goals

- Goals：对话链路的关键不变量可自动验证；测试运行快（不依赖 Milvus / Ollama / TEI）。
- Non-Goals：不做端到端浏览器测试（演示验收仍靠手工与 `deploy` 流程）；不追求覆盖率数字。

## Decisions

**D1 用接口级替身，不 mock 框架内部**
在测试里提供假的模型实现与假的检索结果，通过现有接口注入；不改生产代码、不加测试专用分支。
理由：测试替身跟随接口走，接口稳定则测试稳定；一旦为了测试改生产分支，测试就失去意义。
被否方案：起一个本地假 HTTP 服务模拟 Ollama——依赖端口与启动顺序，慢且脆。

**D2 事件顺序用「收集器」断言，而不是逐条 if**
把 SSE 事件按类型收集后对序列做整体断言（引用 → 可选思考 → 增量 → 结束）。
理由：D13 记录的问题都是顺序问题，序列断言能直接表达"不变量"，失败信息也直观。

**D3 思考过程与正文分离用"双向断言"**
既要断言思考内容出现在思考事件里，也要断言它**不出现**在正文增量与落库内容中。
理由：只断言前者会漏掉"顺便也进了正文"这种回归。

**D4 失败路径必须有用例**
模型调用失败、检索失败、形态不支持三类各一条，断言错误可读且被向上传递（不吞错）。
理由：根 `AGENTS.md` 明确"不吞错、不静默失败"，这条纪律需要测试兜住。

## Risks / Trade-offs

- [替身与真实实现的差异掩盖 bug] → 保留最少量的真机集成测试（已有），替身只覆盖链路逻辑
- [测试过度绑定内部结构，重构就红] → 只断言对外可观察的东西：事件类型序列、落库内容、错误语义
